# ADR-0014: 客户端登录、验证码与服务端接口契约存在漂移

- **状态**: PROPOSED
- **分类**: DEF
- **优先级**: P0
- **影响维度**: 生产功能 / 安全合规
- **日期**: 2026-11-24
- **来源**: 全项目源码审计与静态核验；2026-11-24 在 `legacy-flutter-3.41.9` 分支复核
- **修复 commit**: —

> 仅登记，暂不修复业务逻辑。修复前需先确定服务端权威接口契约。

## 背景（Context）

1. 桌面端向 `${apiBaseUrl}sync/login` 发送 `email/password`，而移动端及服务端登录契约使用手机号/密码/图形验证码；桌面同步适配器未携带 Bearer、Cookie 或验证码。证据：
   - `lib/features/sync/infrastructure/sync_remote_data_source.dart` 的 `login()`。
   - `../flutter_planstar_app/lib/app/network/ps_network_interceptor.dart` 的登录与验证码处理。
   - `../planstar_kratos_server/planstar_backend/internal/service/service.go` 的路由注册。
2. 桌面端登录成功把用户输入的明文密码写入名为 `planstar.token` 的密钥存储；失败则创建本地账号并提示“已切换本地账号”。用户无法据此判断是否真正建立云端同步能力。证据：`lib/features/sync/application/sync_controller.dart:80-99`。
3. 桌面端 `syncNow()` 只提交 `accountId/dirty/since`，没有上传或下载日历、便签、倒数日等业务数据；“每个整点自动同步”开关只持久化布尔值，没有定时器或调度器。证据：`lib/features/sync/application/sync_controller.dart`、`lib/features/sync/presentation/account_page.dart:147`。
4. 移动端声明了 `v1/proxyBuyOrder/myOrders`、`v1/pinTuanOrder/myOrders`、`v1/pinTuanOrder/make`、`v1/pinTuanCampaign/{id}`，但服务端注册表未提供对应路由。证据：`../flutter_planstar_app/lib/app/network/api_paths.dart:58-64` 与后端 `service.go` 的对照。
5. 移动端拦截器对登录/发送验证码响应无条件清空 `psCaptcha`，而后端可能在参数校验等消费验证码之前提前返回，导致用户必须重复获取验证码。证据：`../flutter_planstar_app/lib/app/network/ps_network_interceptor.dart:91`、`lib/app/network/ps_request_context.dart:38-45`。

## 决策（Decision）

- 暂不修改客户端或服务端业务实现。
- 后续以服务端实际路由和响应契约为单一真实源，先形成接口矩阵，再决定桌面端兼容移动端鉴权还是提供独立同步接口。
- 登录降级、密码/token 存储、验证码消费语义和自动同步能力必须在修复方案中一并定义；不得以“本地账号成功”替代“云端登录成功”。
- 服务端补齐缺失路由或客户端下线相应入口，需产品与后端共同确认，属于外部协作项。

## 后果（Consequences）

- **正面**: 避免继续依据不一致的契约开发，降低误登录、伪同步和验证码重试成本。
- **负面/风险**: 修复涉及移动端、桌面端和后端多方；在契约确定前相关真实模式功能不可视为可用。
- **中性**: ADR 仅建立问题基线，不改变当前数据格式或端口契约。

## 验证（Verification）

- 对登录成功、密码错误、验证码错误、服务端提前参数校验失败四类响应做契约测试，断言验证码仅在服务端实际消费后清除。
- 对 ADR 列出的四个移动端路径逐一检查服务端路由注册，并要求集成测试返回非 404 或明确由产品确认下线。
- 桌面端真实模式登录后断言请求包含权威鉴权信息，且存储中不存在明文密码。
- 主窗口与子窗口各修改一类业务数据，执行手动及定时同步，验证另一端能读到对应变更；关闭调度开关后不再产生周期任务。
