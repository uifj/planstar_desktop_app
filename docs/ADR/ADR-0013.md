# ADR-0013: 浮层 clamp 从存储原值出发，修复启动期瞬态小 view 压扁卡片位置

- **状态**: IMPLEMENTED（待提交）
- **分类**: DEF
- **优先级**: P1
- **影响维度**: 桌面组件状态持久化 / 用户可见位置丢失
- **日期**: 2026-11-19
- **来源**: 安装版运行时截图像素对账（卡片渲染位置 ≠ 盘上存储位置）
- **修复 commit**: —

## 背景（Context）

- 现象：安装版启动后桌面卡片渲染在逻辑 (280,0)，而 DataHub
  `planstar.desktop.card.v2` 存的是 (640,16,1000,1016)；宽高还原正确、坐标丢失。
  退出时 `dispose`/生命周期回调会把压扁后的坐标回写盘，造成**永久性位置丢失**。
- 触发链：
  1. `DesktopMultiWindowGateway.openDesktopWidget` 以
     `WindowRect(0, 0, 1920, 1080)` 创建子窗口
     （`lib/infrastructure/desktop_adapters.dart:423`），该尺寸按物理像素生效，
     150% DPI 下子 engine view 的逻辑尺寸仅 1280×720。
  2. 全屏化发生在其后的 `configureOverlay(enable: true)`
     （`lib/windows/desktop_widget_app.dart:252`，postFrame 回调）。
  3. `_loadPosition` 读盘后立即 `_clampToScreen()`（修复前 :299），此刻
     `_screen`/views/`_nativeMetrics`（fallback 1920×1080 物理）全部指向
     1280×720：`maxX = 1280-1000 = 280`、`maxY = 720-1016 < 0 → 0`，
     存储坐标 (640,16) 被压成 (280,0)。
  4. clamp 是**破坏性**的：从「上一次 clamp 结果」出发，全屏尺寸到达后
     `maxX/maxY` 变大也不会把坐标恢复回来。
- 像素证据：`PrintWindow` 截图非黑像素 bbox = 物理 (420,0) 1500×1524
  → 逻辑 (280,0) 1000×1016，与上述 clamp 算式逐字吻合（修复前）。
- 回归用例先红：`test/desktop_card_position_test.dart` 以 1920×1080 物理 +
  dpr 1.5 的 view 泵入 `DesktopWidgetApp`，fake 网关在全屏尺寸到达后记录
  `setRegion` 矩形；修复前 `Expected: <960.0> Actual: <420.0>`（280×1.5），
  修复后绿。

## 决策（Decision）

1. 新增 `_restoredOrigin`（`Offset?`）：`_loadPosition` 读盘合并后记录存储原值；
   `_clampToScreen` 的 x/y 一律从 `_restoredOrigin ?? 当前几何` 出发 clamp，
   屏幕尺寸后续变大时坐标可恢复（`desktop_widget_app.dart` 几何域）。
2. 用户拖拽/调整接管几何时失效：`_beginDrag` / `_beginResize` 置
   `_restoredOrigin = null`，此后 clamp 回到「从当前几何出发」的原有语义，
   不会把用户拖到的位置 snap 回存储值。
3. 候选取舍：
   - 创建子窗口时先查屏幕尺寸再定 rect：要改 `MultiWindowGateway` 公共契约
     且多显示器/混合 DPI 下创建期尺寸仍可能瞬态，弃。
   - 推迟首次 clamp 到 `configureOverlay` 之后：依赖原生调用成功与时序，
     失败路径（overlay 配置不可用）会失去 clamp 保护，弃。
   - 单调放大「见过的最大屏幕」：显示器拔插变小后不再收敛，弃。
   - 存储原值作为 clamp 基准（选定）：单点、与窗口时序解耦、可被 widget 测试守住。
4. 不改 `_screenSize` 的「取各来源最大」策略：它防的是另一类错误（子窗口
   view 偏小把卡片缩小），与本缺陷正交，保留。

## 后果（Consequences）

- **正面**: 启动期任何瞬态 view 尺寸都不再破坏存储坐标；显示器热插拔后
  clamp 仍从权威存储值收敛；退出回写不再丢失用户摆放位置。
- **负面/风险**: 用户首次拖拽前若屏幕合法变小，卡片会按存储原值 clamp 到
  新边界（期望行为）；拖拽开始后存储原值失效，无回 snap 副作用。
- **中性**: 根测试 82 → 83；几何域新增一个可空字段，无公共契约变化。

## 验证（Verification）

- 红→绿：`flutter test test/desktop_card_position_test.dart` 修复前
  `Expected: <960.0> Actual: <420.0>`，修复后 `+1: All tests passed!`。
- `flutter analyze` 0 issue；`dart analyze --fatal-infos`（改动两文件）0；
  根 `flutter test` 83 绿。
- `flutter build windows --debug` 79.7s 通过；重装后运行时截图 bbox =
  物理 (960,24) 1500×1524 → 逻辑 (640,16) 1000×1016，与盘上
  `planstar.desktop.card.v2` 逐字一致；盘上 revision/坐标未被启动期改写。
- 门禁盲区：widget 测试用 fake 网关观察 `setRegion`，不覆盖原生
  `SetWindowRgn` 本身；运行时 bbox 像素对账补上这一形态的证据。
