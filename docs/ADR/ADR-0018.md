# ADR-0018: 客户端凭据、Android 权限与后台最小权限需要整改

- **状态**: PROPOSED
- **分类**: SEC
- **优先级**: P0
- **影响维度**: 安全合规 / 生产功能
- **日期**: 2026-11-24
- **来源**: 安全边界与最小权限专项审计；2026-11-24 在 `legacy-flutter-3.41.9` 分支复核
- **修复 commit**: —

> 仅登记，不复制任何真实密钥值，也不在本次运行 macOS 桌面端时改动其他仓库。

## 背景（Context）

1. 移动端 `android/app/src/main/AndroidManifest.xml` 内含百度地图及多家推送 SDK 的明文标识/密钥元数据。Android APK 可被解包，这些值不能视为服务端秘密；若对应平台支持秘密密钥，泄露会影响配额与滥用风险。证据：该清单 `application` 下的 SDK `meta-data`，本 ADR 有意不复述值。
2. 同一清单声明了相机、闪光灯、精确定位、后台定位、电话状态、安装包、媒体读取及 `QUERY_ALL_PACKAGES` 等权限；是否均为当前已接线功能所必需缺少逐项说明。证据：`../flutter_planstar_app/android/app/src/main/AndroidManifest.xml:3-30`。
3. 后端应用账号初始化脚本把 `planstar_admin` 与十个业务库一起授予 SELECT/INSERT/UPDATE/DELETE/EXECUTE。主应用因此拥有管理库 DML 权限，违背管理面与业务面隔离的最小权限原则。证据：`../planstar_kratos_server/planstar_backend/sql/22_create_app_user.sh:15-27`。
4. Admin 登录限流器在 Redis 错误时明确 `return true`，故障期间退化为不限流，存在撞库与暴力尝试风险。证据：`../planstar_kratos_server/planstar_frontend/admin/internal/service/admin.go:113-125`。

## 决策（Decision）

- 暂不轮换凭据、修改权限清单或数据库授权，避免在未确认部署依赖时造成服务中断。
- 后续由移动端、后端与运维协作完成整改：
  - 将可公开的 Android SDK App ID 与必须保密的 App Secret/API Key 分离，秘密通过服务端或安全配置渠道管理；已暴露的秘密按平台能力评估轮换。
  - 按实际功能逐项删除未使用权限；确需 `QUERY_ALL_PACKAGES`、后台定位、安装包等敏感能力时，补充用途、用户授权路径和商店合规说明。
  - 主应用账号移除 `planstar_admin` 权限，管理服务使用独立最小权限账号；通过迁移脚本平滑切换。
  - 明确 Redis 故障时的安全策略，采用 fail-closed、本地限流或受控降级，并增加告警。
- 密钥扫描与权限审查应进入发布门禁，但不得把真实值写入日志、ADR 或测试快照。

## 后果（Consequences）

- **正面**: 降低凭据滥用、越权访问与撞库风险，提高应用商店合规可解释性。
- **负面/风险**: 凭据轮换与数据库账号切换需要发布窗口和回滚方案；敏感权限删减可能影响尚未验证的功能。
- **中性**: 本 ADR 只记录风险与决策方向，不声称已完成安全整改。

## 验证（Verification）

- 对 Git 历史、APK、构建产物及日志执行秘密扫描，断言不包含服务端秘密；已轮换旧凭据按平台验证失效。
- 使用 `apkanalyzer manifest permissions` 或等价工具列出最终合并清单，逐项对应功能与运行时授权测试。
- 使用独立应用账号连接数据库，断言无法读写 `planstar_admin`，且业务库 DML 正常。
- 注入 Redis 超时/不可用，验证 Admin 登录仍执行明确的安全策略并触发告警；正常路径限流计数准确。
- 完成敏感权限拒绝、仅使用时允许、永久拒绝三种路径的端到端测试。
