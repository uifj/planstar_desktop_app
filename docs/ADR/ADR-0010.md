# ADR-0010: 子 engine 只注册多 engine 安全插件子集，runner 显式声明 /utf-8

- **状态**: IMPLEMENTED（待提交）
- **分类**: DEF
- **优先级**: P0
- **影响维度**: 生产功能 / 评估阻断
- **日期**: 2026-11-18
- **来源**: ADR-0004+0002b 实施期双 engine 运行时冒烟（AGENTS.md §7 门禁）
- **修复 commit**: e641af2

## 背景（Context）

1. **auto_updater 进程级单例导致子 engine 注册即 abort**。依赖迁移后
   `windows/flutter/generated_plugin_registrant.cc` 含 4 个原生插件
   （audioplayers / auto_updater / desktop_multi_window /
   flutter_secure_storage）。`auto_updater_windows 1.0.0` 的 `AutoUpdater`
   构造函数检查进程级静态单例，第二次构造直接
   `throw std::invalid_argument("AutoUpdater has already been initialized")`
   （pub cache `auto_updater_windows-1.0.0/windows/auto_updater.cpp`）。
   desktop_multi_window 0.3.1 的子窗口与主窗口是**同进程不同 engine**，
   runner 的 `DesktopMultiWindowSetWindowCreatedCallback` 原先对子 engine
   走整份 `RegisterPlugins` → 第二次构造抛异常 → 未捕获 C++ 异常
   （0xE06D7363）→ terminate → abort() → CRT「Debug Error! abort() has
   been called」模态对话框**冻死主平台线程**，`openDesktopWidget` 永不返回。
   证据：WER dump `planstar_desktop_app.exe.36196.dmp`（18:28）异常流
   code=0xE06D7363，异常对象 vtable 落在 auto_updater_windows_plugin.dll，
   throw 点下方栈帧为 AudioplayersWindowsPluginRegisterWithRegistrar；
   对话框线程即主平台线程。auto_updater 在 Dart 层零调用
   （AGENTS.md §10 已声明未接线，需 appcast 更新源）。
2. **MSVC C4819 阻断构建**。runner 源码中文注释为 UTF-8 无 BOM，
   MSVC 默认按代码页 936 解读报 C4819，而 `apply_standard_settings`
   开了 /WX → C2220 构建失败。
3. **间歇性 Intel D3D11 驱动 AV（已知环境风险，非本项目代码缺陷）**。
   在重取证负载下（并行解析 1.6GB 全量 dump、baseline worktree 构建、
   VM service 高频探测）第二视图 raster 线程偶发 0xC0000005
   （写 0x8 / 0x4a0），ExceptionAddress 全部落在 Intel 用户态驱动
   `igd10umt64xe.DLL`（如 `47596.dmp` ExceptionAddress=
   igd10umt64xe.DLL+0xDAA30，18:35），项目模块无故障帧。
   卸载取证负载后连续 3 次 95 秒冒烟（A/B/C，18:44–18:49）全部健康。
   同批还观察到一次子 engine 启动延迟 78 秒的异常样本（18:33 run，
   随后崩溃），正常样本子 engine notify 初始化延迟仅 3–7 秒。
   **补充（ADR-0005 实施期，19:09–19:22）**：无取证负载下启动期仍间歇
   0xC0000005 读近空地址（0x4a0/0x5a8），fault 落在 flutter_windows.dll
   （Impeller OpenGLES 启动期 GPU 表面初始化，偏移 +0xF311BC/+0xEF6A1A），
   栈含 igd10umt64xe.DLL 帧。为排除 ADR-0005 反应器启动期构造 AudioPlayer
   的嫌疑，做了 A/B：临时禁用主/子窗口两处 `ref.read(soundReactionProvider)`
   重新构建，崩溃仍复现且签名一致（禁用组 1/4 崩、启用组 2/4 崩，样本相近），
   确认与 Dart 接线无关，属同一 Intel 驱动环境风险。恢复接线后持续冒烟
   （20 秒 + 80 秒）健康、overlay 签名与基线一致。结论：该 AV 可在任意启动
   偶发（不限重负载），健康实例门禁不受影响；复现时按决策 3 收 dump 核对归属。

## 决策（Decision）

1. **子 engine 注册子集**：runner 回调只注册多 engine 安全的插件——
   audioplayers（子 engine 启动期也构造 AudioPlayer，通道必须在；
   跨 engine 不发声由 Dart 层不变量保证，见 ADR-0005）、
   desktop_multi_window、flutter_secure_storage，再加
   `RegisterDataHubPlugin` 与 `RegisterDesktopWallpaperPlugin`。
   **不注册 auto_updater**（进程级单例）。约束写入 runner 注释。
2. **/utf-8 显式声明**：`windows/runner/CMakeLists.txt` 增加
   `target_compile_options(${BINARY_NAME} PRIVATE /utf-8)`。
3. **Intel 驱动间歇 AV 登记为已知环境风险**：现有证据不支持在项目代码
   内加 workaround（故障帧全在驱动内、正常负载 3/3 健康）。后续若复现：
   先收 WER dump 核对 ExceptionAddress 归属，再考虑 Impeller 开关 A/B
   或更新 GPU 驱动；不得以放宽冒烟门禁「变绿」。

候选取舍：
- 「给 auto_updater 包一层 try/catch 吞异常」：掩盖进程级单例契约，
  且 abort 发生在 CRT 层难以可靠拦截，弃用。
- 「子 engine 完全不注册 audioplayers」：实测子 engine 启动期
  GlobalAudioScope.ensureInitialized 构造 AudioPlayer 触发
  MissingPluginException，弃用。
- 「注释改 ASCII 规避 C4819」：违反 AGENTS.md §6 中文注释约定，弃用。

## 后果（Consequences）

- **正面**: 子 engine 启动不再 abort；overlay 冒烟 3/3 健康；
  中文注释与 /WX 共存，构建稳定。
- **负面/风险**: 子集清单需与主 engine registrant 人工同步——新增原生
  插件时必须评估多 engine 安全性（进程级单例/全局钩子一律只进主 engine）；
  auto_updater 未来接线时只能注册在主 engine。Intel 驱动间歇 AV 仍可能
  在极端负载下复现，已登记为环境风险。
- **中性**: 桌面壁纸/DataHub 通道按 engine 注册的既有模式不变。

## 验证（Verification）

- `flutter build windows --debug` 通过（无 C4819/C2220）。
- 3×95 秒冒烟（smoke A/B/C）：`verify_desktop_widget.ps1` 输出
  overlay `style=0x94000000 ex=0x80 region=3 rect=0,0,1707x1067`、
  `regionBox=280,0 -> 1280,1016`、hit semantics
  `(60,60)=PASS-THROUGH (300,300)/(448,378)/(900,300)=HIT`；
  `tasklist` 核实进程存活后清理。
- 双 engine notify 初始化日志齐全，子 engine 延迟 3–7 秒。
- grep 断言：runner 回调内无 AutoUpdater 注册。
