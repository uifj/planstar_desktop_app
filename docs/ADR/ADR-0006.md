# ADR-0006: 表现层重建收敛——值相等、回调上抛、select 与桌面组件 State 拆分

- **状态**: IMPLEMENTED（待提交）
- **分类**: DEBT
- **优先级**: P2
- **影响维度**: 生产功能
- **日期**: 2026-11-18
- **来源**: 全量审计（docs/arch_optimize.txt P2-1/P2-2/P2-3）+ 逐条代码核实
- **修复 commit**: e641af2

## 背景（Context）

1. **读模型身份相等导致全网格重建**：CalendarDayModel / EventOccurrence /
   MonthData 均 const 构造但无 ==/hashCode 重载
   （calendar_controllers.dart:354-361/363-387/389-401），monthDataProvider
   每次重算产出全部新对象 → 最多 126 个 DayCellWidget 全部重建，哪怕只变一天。
2. **闭包放大**：MonthGrid._column 每 cell 现造 5 个闭包
   （month_grid.dart:79-85：onTap/onDoubleTap/onSecondaryTap/onToggleLine/
   onToggleEvent），widget 级短路不可能生效。
3. **watch 面过宽**：lib/ 下 `ref.watch(` 共 **72 处/31 文件**；
   Riverpod 选择器 `.select((` **全仓 0 处**（审计称 3 处，核实那 3 处是
   SelectedDateController.select(date) 业务方法，calendar_page.dart:64/67/156）。
   CalendarPage.build watch calendarControllerProvider（calendar_page.dart:31）
   只为读 error（:38/:42）与 loading（:55），events/cells 一变整个 Column
   连带 MonthGrid 重建。
4. **每 cell 一个滚动视口**：day_cell_widget.dart:85-87
   `Expanded(child: SingleChildScrollView(child: Column(...)))`，126 个独立
   viewport + ScrollController + RenderViewport 每帧参与布局。行高写死在
   month_grid.dart:62（singleLine 96 / 普通 112，审计称在 day_cell_widget，已修正），
   内容超出应裁剪而非滚动。
5. **桌面组件单 State 巨石化**：lib/windows/desktop_widget_app.dart 共 **1813 行**，
   _DesktopWidgetAppState 从 :57 到文件末尾，**17 处 setState**
   （169/194/204/324/337/456/483/508/517/567/589/617/712/717/723/745/1766），
   其中空刷新 `setState(() {})` 在 **:337/:483**（审计称 328/474，已修正）；
   _activeLineId:107、_paletteTarget:108、_confirmClear:109 等任一字段变化
   → 整棵桌面组件树（含完整月历网格）重建。该窗口常驻桌面，重建成本持续付。
   **反面不用改**：_pushRegion（:279-308）拖动时先
   `setRegion(rects: [], dragging: true)` 放开整窗（:317-319）、松手重推（:339），
   缩放同模式（:389-391）——已做对，保留。

## 决策（Decision）

按成本递增分四步，每步独立提交、独立可验证：

1. **读模型值相等**：CalendarDayModel/EventOccurrence/MonthData 继承 core 包
   ValueObject（深比较/深哈希已具备，不引 freezed）。落地位置为 ADR-0004
   拆出的 presentation/read_model/month_data.dart。
2. **MonthGrid 回调上抛**：cell 回调改为把 day 往上抛（`onTap(day)` 而非
   `onTap: () => onTap(day)`），闭包数 126×5 → 5。DayCellWidget 配合改为
   接收 day + 稳定回调引用。
3. **watch 收敛**：CalendarPage 用 `.select((s) => s.error)` /
   `.select((s) => s.loading)` 拆读；其余 71 处 watch 按热路径优先逐步收敛
   （不一次性全改，避免行为回归面过大）。终极形态：monthDataProvider 拆为
   `visibleDaysProvider`（日期骨架，依赖 settings+navigation）+
   `dayModelProvider(date)` family（依赖 events/cells），翻月与改数据互不牵连。
4. **cell 裁剪替代滚动**：SingleChildScrollView → ClipRect + Column
   （行高固定，超出裁剪）。**这是行为变化**（原可滚动查看溢出内容），
   实施前目视确认溢出场景可接受，必要时保留长按展开浮层兜底。
5. **desktop_widget_app 拆分**：按「卡片几何（位置/尺寸/拖动）」「编辑器浮层」
   「调色板」「月历网格」拆独立 widget；几何状态用 ValueNotifier 或局部
   provider 隔离 setState 域；两处空刷新改为定向通知。_pushRegion 拖动
   链路原样保留。窗口/托盘/屏幕 API 继续走三大封装包公开新 API
   （AGENTS.md §5），拆分不改适配器契约。

候选取舍：
- 「RepaintBoundary 包 cell」：只隔离绘制不隔离 build/layout，对本问题
  （重建而非重绘）收益有限，不作为主手段。
- 「桌面组件改 Riverpod 全局状态」：该窗口是独立 engine/入口，
  局部 ValueNotifier 足够，不引入跨窗口状态耦合。

## 后果（Consequences）

- **正面**: 单日变更只重建受影响 cell；翻月不再触发数据侧 watch 连锁；
  126 个滚动视口的布局开销消失；桌面常驻窗口重建域收窄到实际变化部件。
- **负面/风险**: 值相等引入深比较成本（读模型字段少，远小于重建成本）；
  裁剪替代滚动是可见行为变化需确认；desktop_widget 拆分触及命中区域/
  浮层手势等已修复过的敏感区（近期 audit commit 涉及），须回归自检脚本。
- **中性**: 为后续 Impeller SDF 桌面渲染（Flutter 3.50 已默认）减少无谓图元。

## 验证（Verification）

- 新增 widget 测试：单日数据变更时其余 DayCellWidget 的 build 计数不增
  （以测试桩计数）；值相等断言（同内容两实例 ==）。
- `flutter analyze` 0 error/0 warning；现有测试全绿。
- `flutter build windows --debug` + 运行时冒烟（tasklist 核实，AGENTS.md §7）。
- 桌面 overlay/命中区域：`powershell -File windows/installer/verify_desktop_widget.ps1`
  自检并附输出；拖动/缩放/调色板/编辑器浮层手工回归。
- DevTools timeline 对比：勾选单日时 build/layout 耗时与重建 cell 数，数据回填本 ADR。

## 实施记录（2026-11-19）

### 步骤 1–4（主窗口读模型，已运行时验证）

- **步骤1 值相等**：`TimelineTag` / `TimelineBarEntry`（core/ports/timeline.dart）、
  `CalendarDayMeta`（core/calendar_math.dart）、`EventOccurrence` /
  `CalendarDayModel` / `MonthData` / 新增 `VisibleDays`
  （presentation/read_model/month_data.dart）全部继承 core 包 `ValueObject`，
  按属性深比较/深哈希，不引 freezed。
- **步骤2 回调上抛**：`MonthGrid` 改 ConsumerWidget，cell 回调统一把 `day`
  上抛（`onTap(day)` 等 5 个稳定引用），闭包数 126×5 → 5；`DayCellWidget`
  拆为 ConsumerWidget（watch `dayModelProvider(date)` +
  `selectedDateProvider.select((d) => d == date)`）+ 无状态 `_DayCellView`。
- **步骤3 watch 收敛**：`CalendarPage` 改 `.select((s) => s.error)` /
  `.select((s) => s.loading)`；新增 `visibleDaysProvider`（日期骨架，依赖
  settings+navigation+clock）、`calendarExpansionsProvider`（按 events 身份
  共享重复展开，避免翻月回归）、`dayModelProvider(date)` family、
  `countdownBarProvider`。`CalendarReadModelAssembler` 抽出 `skeleton` /
  `expansionsOf` / `day` 单一真实源，`monthDataProvider` 保留供桌面/壁纸路径。
- **步骤4 裁剪替代滚动**：`_DayCellView` 用
  `ClipRect + OverflowBox(maxHeight: infinity) + Column(min)` 替代
  `SingleChildScrollView`，溢出裁剪而非滚动，完整内容仍由浮层编辑器查看。
- **验证**：新增 `test/calendar_rebuild_test.dart`（6 用例）——值相等断言 +
  「单日变更只通知该日 dayModelProvider」+ 以 `debugOnRebuildDirtyWidget`
  钩子实测「单日变更只重建 1 个 DayCellWidget」（rebuilds==1，非放宽断言）。
  根工程测试 **81 全绿**（原 75 + 6）；`dart analyze --fatal-infos` 0 告警；
  `flutter build windows --debug` 通过；运行时冒烟健康（双 engine、
  notify count=2、overlay 命中区域基线一致）。

### 步骤 5（桌面组件拆分，已实施 + 静态验证；运行时 overlay 回归受环境阻塞）

- **几何域隔离**：新增 `_Geometry`（x/y/width/height/popupRect）与 `_Editing`
  （selectedDate/editingDate/popupDate/paletteTarget/confirmClear/recentColors）
  两个值对象，各由独立 `ValueNotifier` 持有。`build()` 用
  `ValueListenableBuilder<_Geometry>` 定位卡片，卡片内容 `_DesktopCard` 作为
  **缓存 child**——拖动/缩放（高频 pointer）只重定位，不重建 42 格网格。
- **拆独立 widget**：`_DesktopCard`（watch monthDataProvider +
  settingsControllerProvider，内嵌 `ValueListenableBuilder<_Editing>`）、
  `_DesktopGrid`（月历网格）、`_PopupEditor`（编辑器浮层，监听编辑域）、
  `_PaletteStrip`（调色板，卡片底部与浮层复用）。
- **两处空刷新定向化**：`_endDrag` / `_endResize` 原 `setState(() {})` 改为
  几何 notifier 的定向赋值（snap 后 `copyWith` 通知）。全部 17 处 setState
  收敛为几何/编辑两域 notifier 写入，文件内不再有任何 setState。
- **敏感逻辑原样保留**：`_pushRegion` 签名去重 + 拖动/缩放
  `setRegion(rects: [], dragging: true)` 放开整窗链路、8px 吸附、屏幕边界
  clamp、350ms 双击判定、浮层 inflate(16) 命中容差、启动 1500ms resize 冷却
  全部逐行保留。窗口/托盘/屏幕仍走三大封装包公开 API，适配器契约未改。
- **保真细节**：`_activeLineId`（聚焦行）**不纳入** `_Editing` 通知域——
  原实现聚焦时静默赋值不 setState，纳入会在打字聚焦时重建浮层、扰乱光标；
  保留为 State 普通字段，仅动作/调色板按需读取。
- **静态验证**：`dart analyze --fatal-infos` 全仓 **No issues found**；
  根工程 **81 测试全绿**；`flutter build windows --debug` 通过（102.4s）。
- **运行时验证缺口（诚实登记）**：本次 8 次启动（含 60s 长等待）overlay
  子 engine 的 Dart isolate 均未启动——只创建 GL surface，无 VM service /
  notify 日志、无异常，主 engine 每次健康（notify count=1）。该停滞点在
  `bootstrap.dart:89` 的 `notificationGateway.initialize()`（首个 await
  `DataHubStore.create()` 之后、`runApp`(:165) 之前），**早于** DesktopWidgetApp
  构建，故与本次 widget 重构无因果（重构代码在这些启动中根本未被执行）。
  属 ADR-0010 记录的子 engine 启动环境类故障，本次持续复现（非偶发）。
  因此 `verify_desktop_widget.ps1` 未能取得健康 overlay 基线，**拖动/缩放/
  调色板/编辑器浮层的手工目视回归仍待一次健康启动后补做**；不以静态绿
  伪装运行时已验证。DevTools timeline 对比同样待健康启动后回填。
