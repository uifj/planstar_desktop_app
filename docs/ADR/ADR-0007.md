# ADR-0007: DataHub 通道 Pigeon 化（Windows 平台通道模式），替换手写 MethodChannel/EventChannel

- **状态**: IMPLEMENTED（待提交）
- **分类**: ARC
- **优先级**: P1
- **影响维度**: 幻觉源 / 安全合规 / 生产功能
- **日期**: 2026-11-18
- **来源**: AGENTS.md §5「优先使用 Pigeon 跨 engine 与平台进行数据同步」+
  Flutter 3.50 官方互操作公告核实 + 代码核实
- **修复 commit**: —

## 背景（Context）

1. **现状是手写字符串通道**：Dart 侧 `MethodChannel('planstar/data_hub')` +
   `EventChannel('planstar/data_hub_events')`（data_hub.dart:29-30/:117-118/:151）；
   C++ 侧 `HandleCall` 按方法名字符串分发 configure/snapshot/write/delete/clear
   （data_hub_plugin.cpp:39-40/:328-362），参数经 `StringAt` 手工取键。
   方法名/键名拼写错误是运行时 bug 而非编译期错误，双端契约无单一真实源。
2. **AGENTS.md §5 已立规**：优先使用 Pigeon 跨 engine 与平台进行数据同步，
   不直接调用 MethodChannel/EventChannel。pigeon ^30.0.4 已在 dev_dependencies
   （lock 解析 30.0.4）但**尚未生成任何通道代码**（AGENTS.md §10 登记的缺口）。
3. **Flutter 3.50 / Dart 3.14 互操作现状（官方博客 2026-11-11/11-12 核实）**：
   - 直接原生互操作稳定：FFIgen（C/Objective-C）与 JNIgen（Java/Kotlin）stable。
   - **Pigeon v30 的 native interop 模式是 preview，仅支持 Android/iOS/macOS**；
     **Windows/Linux 上 Pigeon 仍走平台通道**，同一 Pigeon 定义文件可生成两种模式。
   - 本地 pigeon 30.0.4 native_interop_guide.md 核实：interop 模式不支持
     `@EventChannelApi`/`@TaskQueue`/`@ProxyApi`；DataHub 的广播流依赖
     EventChannel，即便未来 Windows 支持 interop 也须拆分文件。
   - 结论：**本项目（Windows 为主）当前正确形态是 Pigeon 平台通道模式 +
     CppOptions**，不是 FFI 直连；不追 preview。
4. DataHub 的进程级单例 + 全量快照 + 失败回滚 + revision 单调语义是已验收设计
   （docs/cross-engine-sync-analysis.md §4.1，2026-11-16 验收；
   data_hub_plugin.cpp:137-163 回滚、:247-275 原子替换），**本 ADR 只换通道层，
   不动同步语义**。

## 决策（Decision）

1. **定义 `pigeons/data_hub.dart`**：`@HostApi` 声明 configure/snapshot/write/
   delete/clear（参数与返回为类型化数据类：DataHubSnapshot、WriteResult 等，
   取代 EncodableMap 手取键）；`@EventChannelApi` 声明广播流
   （DataChange 载荷：key/revision/origin/deleted/value）。
   `@ConfigurePigeon` 输出 Dart 至 lib/infrastructure/generated/、
   C++ 至 windows/runner/generated/（cppOptions）。
2. **C++ 侧实现生成的 HostApi 接口**，内部直接委托现有 DataHub 单例
   （Instance()/Write/Delete/Clear/Snapshot/Configure 原样复用），
   广播 StreamHandler 复用现有 sinks 机制。删除手写 HandleCall 字符串分发。
3. **Dart 侧 DataHubStore 改用生成的 HostApi/事件流**，
   `KeyValueStore + StorageReloader + CrossEngineSync` 三端口实现不变
   （data_hub.dart:55-56），非 Windows 的 _LocalBackend 降级路径（:280 起）保留。
4. **双端同一 commit 切换**：Pigeon 生成的通道名与旧名不同，不做双通道并存
   过渡（同进程内双端原子切换，无外部兼容面）。生成文件不手改
   （AGENTS.md §6 单一真实源）。
5. **不采用 native interop 模式**（Windows 不支持 + EventChannelApi 限制）；
   在 pigeons/data_hub.dart 头注释登记该约束与复查条件（Pigeon 官方宣布
   Windows interop 支持时重评）。
6. 原生侧增量落盘**不在本 ADR 范围**：全量快照 + WRITE_THROUGH 是正确性设计，
   当前数据量下非主要矛盾（见 ADR-0002 决策取舍）；存储格式终态见 ADR-0008。

候选取舍：
- 「保持手写通道」：违反 AGENTS.md §5，契约双端漂移风险持续存在，弃用。
- 「FFIgen 直绑 C ABI 绕过 Pigeon」：失去类型化契约与生命周期管理，
  且广播流仍需通道，收益不抵复杂度，弃用。
- 「等 Windows interop 稳定再动」：通道模式与 interop 模式共用同一定义文件，
  现在 Pigeon 化即是未来切换的前置，等待无收益。

## 后果（Consequences）

- **正面**: 双端契约编译期校验，拼写类运行时 bug 归零；参数类型化取代
  EncodableMap 手取键；符合 AGENTS.md §5；为未来 interop 模式留好定义文件。
- **负面/风险**: 引入代码生成步骤（改契约须重跑 pigeon，生成物入库）；
  C++ 生成代码与现有 runner 构建集成需调试一次；通道切换期若双端不同步
  会静默失联——以同一 commit + 冒烟测试防住。
- **中性**: DataHub 同步语义、revision/回滚行为、Dart 三端口契约均不变。

## 实施记录（2026-11-18）

### 与决策文字的一处必要修正：广播用 @FlutterApi 而非 @EventChannelApi

决策第 1/2 条原文写「`@EventChannelApi` 声明广播流 / 广播 StreamHandler 复用
sinks」。实施时核实 **Pigeon 30.0.4 的 C++ 生成器不支持 `@EventChannelApi`**
（仅 Swift/Kotlin/Dart 生成器支持），Windows 走 CppOptions 无法生成事件流通道。
因此广播改用 **`@FlutterApi`（host → Dart 主动推送）** 建模：原生层为每个
engine 持有一个 `DataHubFlutterApi` 代理，写入成功后逐一向各代理推送
`DataChangePayload`，取代旧 EventChannel sinks。这更彻底地落实 AGENTS.md §5
（双端通道代码全部由 Pigeon 生成，零手写 MethodChannel/EventChannel 字符串分发），
同步语义（origin 自反馈过滤 + revision 单调 + 失败回滚）完全不变。约束与复查
条件已登记在 pigeons/data_hub.dart 头注释。

### 落地内容

- 新增 `pigeons/data_hub.dart`：`@HostApi DataHubHostApi`（configure/snapshot/
  write/delete/clear/release）+ `@FlutterApi DataHubFlutterApi.dataChanged` +
  数据类 DataHubSnapshot/WriteResult/DataChangePayload。`@ConfigurePigeon` 输出
  Dart 至 lib/infrastructure/generated/data_hub.g.dart、C++ 至
  windows/runner/generated/data_hub.g.{h,cpp}（namespace planstar_data_hub）。
- 重写 `windows/runner/data_hub_plugin.cpp`：DataHub 单例返回类型化 Pigeon 类
  （回滚/原子替换/WRITE_THROUGH 逻辑原样保留），sinks_ → proxies_
  （`vector<shared_ptr<DataHubFlutterApi>>`），Broadcast 构造 DataChangePayload
  经代理推送；新增 `DataHubHostApiImpl` 委托单例，Release 摘除本 engine 代理；
  删除 HandleCall 字符串分发、DataHubStreamHandler、手写通道名常量。
  `RegisterDataHubPlugin` 每 engine 建代理 + AddProxy + SetUp + 进程级向量保活。
- `windows/runner/CMakeLists.txt` 加入 generated/data_hub.g.cpp 编译单元。
- 重写 `lib/infrastructure/data_hub.dart` `_NativeBackend`：改用生成的
  `DataHubHostApi` + 实现 `DataHubFlutterApi.dataChanged`（去重逻辑同旧 _onEvent），
  删除 dataHubMethodChannel/dataHubEventChannel 常量与 flutter/services 导入；
  dispose 经 `release()` + `setUp(null)` 释放。_LocalBackend 降级与冷启动迁移不变。
- bootstrap.dart 注释同步为「Pigeon FlutterApi 广播」。
