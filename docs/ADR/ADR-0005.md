# ADR-0005: 命令副作用统一走领域事件反应，消除提示音硬编码与时序分叉

- **影响维度**: 认知障碍 / 生产功能

## 背景（Context）

项目已有 DomainEventBus（packages/infras/core/lib/src/domain/domain_event_bus.dart:25-68，
runtimeType 精确匹配分发），提醒/历史/同步/桌面控制器均订阅领域事件
（reminder_controller.dart:65-69、history_controller.dart:67-69、
sync_controller.dart:34-40、desktop_controller.dart:74），README 亦声明
「提醒/历史/同步控制器订阅领域事件，彼此不直接依赖」。但提示音开了特例：

1. `toggleEventCompleted`（calendar_controllers.dart:167-176）：
   saveEvent(:172) → **直接 `ref.read(soundGatewayProvider).play(...)`**(:174)
   → load()(:175)。
2. `toggleLineCompleted`（:230-239）：saveCellLines(:235，内部 :220 已 load)
   → play(:236-238)。**两个命令的声音/load 时序相反**。
3. 后果：应用服务知道了音频网关（soundGatewayProvider 声明于
   core_providers.dart:103-105）；测命令逻辑必须 mock 声音；
   声音与重载时序耦合且不一致。
4. 仓储侧的正确范式已存在：`_persist` 落盘成功才 `_dispatch`
   （local_calendar_repository.dart:168-177）。

## 决策（Decision）

把声音纳入既有事件机制，不开特例：

1. **新增显式领域事件 `TaskCompleted`**（携带日期与来源类型：事件/清单行），
   由聚合在「未完成 → 完成」转变时经 `changed()` + `raiseDomainEvent()` 发出
   （遵循 AGENTS.md §4 不可变聚合范式）。不复用 CalendarEventChanged 让
   反应端猜测完成转变——显式事件语义自洽，订阅端零推断。
2. **新增 `SoundReactionHandler`**（application 层反应器，bootstrap 注册订阅）：
   订阅 TaskCompleted，读 settings.taskCompleteTone，经 SoundGateway 播放。
   设置读取在反应器内完成，命令不再接触音频网关。
3. **删除两个命令方法中的直接 play 调用**；时序统一为
   「落盘成功 → 分发事件 → 反应器发声」，与仓储 _dispatch 语义一致。
4. **跨 engine 不变量**：领域事件不跨 engine
   （docs/cross-engine-sync-analysis.md §2.6）。TaskCompleted 只在操作发起
   engine 的本地总线分发，提示音只在操作端响——与现状行为一致；
   其他 engine 经 CrossEngineDataChanged 重载数据但**不**触发 TaskCompleted，
   此不变量写入反应器注释与测试。

候选取舍：
- 「订阅 CalendarEventChanged/DayCellChanged 并检测完成转变」：无需新事件，
  但反应端要对比前后状态，总线当前只投递单事件载荷，需额外携带旧值，
  复杂度高于显式事件，弃用。
- 「声音保留在命令但统一时序」：只治时序不治耦合，应用服务仍依赖音频网关，弃用。

## 后果（Consequences）

- **正面**: 命令可纯逻辑测试（不 mock 声音）；副作用清单集中在反应器，
  后续加「完成震动/通知」只增订阅不改命令；两命令时序一致。
- **负面/风险**: 事件链路多一跳，发声延迟略增（毫秒级，可接受）；
  须防反应器重复订阅（bootstrap 生命周期管理，参照现有控制器订阅模式）。
- **中性**: SoundGateway 端口契约不变（asset 映射下沉见 ADR-0003）。

## 验证（Verification）

- 新增测试：完成转变发 TaskCompleted、未完成→未完成不发；
  反应器按设置音色播放（fake SoundGateway 计数）；tone=none 不播；
  落盘失败（Fail）不发声；CrossEngineDataChanged 不触发发声。
- 现有测试全绿；`flutter analyze` 0 error/0 warning。
- grep 断言：calendar_controllers.dart（或拆分后的 calendar_controller.dart）
  无 `soundGatewayProvider` 引用。
- 手工冒烟：勾选事件/清单行各一次，声音在数据刷新后响且两端时序一致。

## 实施记录（2026-11-18）

落地与决策一致，命令不再接触音频网关：

1. **显式事件**：`lib/core/app_events.dart` 新增 `TaskCompletionSource{event,cellLine}`
   与 `TaskCompleted`（携带 date/source，注释写明跨 engine 不变量）。
2. **聚合发事件**（不可变范式，先落盘后分发由仓储保证）：
   - `CalendarEvent.markCompleted`：仅 `value && !wasCompleted` 时 raise，
     幂等重标与取消完成都不发（calendar_event.dart:173-194）。
   - `DayCell.withLines`：按行 id 建 before-map，仅「既存行 false→true」发；
     改色/删行/新增即完成的行都不发（day_cell.dart:59-77）。
3. **反应器**：新增 `lib/features/calendar/application/sound_reaction.dart`
   （`SoundReaction` + `soundReactionProvider`，keepAlive/start/onDispose-stop）。
   订阅 TaskCompleted，`toneOf` 读 `settingsControllerProvider.taskCompleteTone`，
   `none` 提前返回；设置读取在反应器内完成。
4. **删命令直 play**：`toggleEventCompleted`/`toggleLineCompleted` 只做状态变更
   与落盘，时序统一「落盘成功→分发→反应器发声」。
5. **接线**：采用应用根 `ref.read(soundReactionProvider)` 初始化（主窗口
   planstar_app.dart:37、子窗口 sub_window_app.dart:46），与提醒/历史控制器
   同一保活模式，而非字面 bootstrap 注册——子窗口 engine 也订阅，保证
   「提示音只在操作发起 engine 响」。

候选取舍补充：反应器构造经 `ref.watch(soundGatewayProvider)` 会在启动期即创建
`AudioPlayer`（audioplayers 6.8.1 构造即调 `_create()` 平台通道）。曾怀疑这是
启动崩溃诱因，A/B 禁用两处接线后崩溃仍复现且签名一致，排除（见下）。

### 验证

- 新增 `test/task_completed_sound_test.dart` 13 例全绿：聚合转变 5 例、
  反应器单元 3 例（按音色播/none 静音/CrossEngineDataChanged 不发声/stop 退订）、
  Provider 链集成 5 例（注册后发声/未注册不触碰网关/清单行发声/落盘失败不发声/
  tone=none 不发声）。none 集成用例需先按应用根接线初始化设置控制器、种子落盘后
  显式 `load()` 重载（与跨 engine 重载路径一致），否则懒创建读到默认 ding。
- 门禁：`flutter analyze` 52 info（=ADR-0009 弃用基线）0 error/0 warning；
  根测试 75、core 154、设计系统 14 全绿；grep `soundGatewayProvider` 于
  calendar_controller.dart = 0；`flutter build windows --debug` 通过。
- 运行时冒烟：overlay 签名 style=0x94000000 ex=0x80 region=3
  rect=0,0,1707x1067 regionBox=280,0→1280,1016，命中语义正确，双 engine
  初始化完成，80 秒存活后清理。
- **启动期 Intel 驱动崩溃（环境风险，非本 ADR 回归）**：冒烟中间歇出现
  0xC0000005 读近空地址（0x4a0/0x5a8），fault 在 flutter_windows.dll
  （Impeller OpenGLES 启动期 GPU 初始化），栈含 igd10umt64xe.DLL。A/B 禁用
  反应器接线后崩溃仍复现、签名一致（两组崩溃率相近），确认与 ADR-0005 无关，
  归入 ADR-0010 已登记的 Intel 显卡驱动环境风险。健康实例冒烟全绿，未放宽任何断言。
