# ADR-0004: 跨 feature 聚合上移为显式装配器，calendar 读模型拆出应用层

- **状态**: IMPLEMENTED（待提交）
- **分类**: ARC
- **优先级**: P1
- **影响维度**: 认知障碍 / 上下文膨胀
- **日期**: 2026-11-18
- **来源**: 全量审计（docs/arch_optimize.txt A2/A3/A8）+ 逐条代码核实
- **修复 commit**: e641af2

## 背景（Context）

1. **calendar 横向依赖 4 个兄弟 feature**（垂直切片原则的反例）：
   calendar_controllers.dart:14-20 import 了 countdown、subscription、
   timetable、settings 的 controller 与 domain；`monthDataProvider`
   （:403-487）直接 `ref.watch` 它们的 state 做聚合（:404-410 共 7 个 watch：
   settings/calendar/monthNavigation/countdown.items/subscription.items/
   timetable.items/clock）。**加一个新 feature 就得改 calendar**。
2. **一个文件五种职责**（calendar_controllers.dart 共 488 行）：
   provider 组合（calendarRepositoryProvider:31-38）、写侧命令
   （CalendarController:75-309）、导航状态（MonthNavigation:332-350）、
   选中态（SelectedDateController:318-325）、读模型
   （EventOccurrence:354-361、CalendarDayModel:363-387、MonthData:389-401、
   monthDataProvider:403-487）。
3. **读模型内容全是表现层塑形**：isCurrentMonth（:384/:470，供淡化渲染）、
   isRestDay 派生（:386）、countdownBar 按 `daysLeft.abs()` 排序（:482-485）、
   weekdayHeaders（:398/:477）。核实修正：中文星期表头文本实际在
   lib/core/calendar_math.dart:142-160，controllers 只是引用。
   这些是视图模型，不是应用服务。
4. **CalendarState.copyWith 的 error 双开关**（:55-67）：
   `error ?? this.error` + `clearError` 两个参数控制同一件事，
   `copyWith(error: null)` 永远清不掉错误（:66），load 成功路径被迫走
   `clearError: true`（:102）。

## 决策（Decision）

A2 与 A3 是同一块代码的两个症状，**一次改动一起做**：

1. **跨 feature 聚合上移**：定义 `TimelineContributor` 端口（「某区间内
   每天有什么」的只读贡献接口，放 lib/core/ports/ 或 calendar 读侧端口），
   countdown/subscription/timetable 各自在 application 层提供实现
   （只读自己的 state）。calendar 侧新增显式 `CalendarReadModelAssembler`
   消费 `List<TimelineContributor>`，贡献者列表在组合根 bootstrap 注册。
   **新 feature 只需注册贡献者，calendar 一行不改**。
   settings/clock 属全局上下文而非 timeline 贡献，继续由读模型直接消费。
2. **文件拆分**（calendar_controllers.dart 一分为三）：
   - `application/calendar_controller.dart`：CalendarState + CalendarController
     （只留写侧命令）+ calendarRepositoryProvider
   - `presentation/calendar_providers.dart`：MonthNavigation、
     SelectedDateController、monthDataProvider（纯函数读模型 Provider，
     符合 AGENTS.md §4）
   - `presentation/read_model/month_data.dart`：MonthData、CalendarDayModel、
     EventOccurrence（视图模型归表现层）
3. **copyWith 单开关化**：error 参数改哨兵模式（`Object? error = _unset`
   私有哨兵常量），显式传 null 即清除，删除 clearError。不引入 freezed
   （项目无此依赖，一个哨兵即可解决）。
4. 与 ADR-0002 第 4/5 子项（cells 改 Map、load 增量）**同批实施**，
   避免对同一文件反复开刀；ADR-0001 的循环反转落在拆出的
   monthDataProvider 新位置。

候选取舍：
- 「calendar 继续聚合但只 import 端口不 import controller」：依赖方向仍
  指向兄弟 feature 的应用层，新增 feature 仍要改 calendar 的 watch 清单，弃用。
- 「引入 freezed 生成状态类」：新增代码生成依赖与学习成本，超出本问题所需，弃用。

涉及目录结构与读模型归属调整，**实施前按 AGENTS.md §3 先经用户确认**。

## 后果（Consequences）

- **正面**: calendar 与兄弟 feature 解耦，垂直切片名副其实；单文件 488 行
  降为三个 ≤200 行文件；error 语义单一，copyWith 误用面消失。
- **负面/风险**: 贡献者抽象引入一层间接（调试聚合问题时多一跳）；
  拆文件波及全部 import 方（calendar_page/widgets/dialogs 等），
  须一次性改完避免中间态。
- **中性**: weekdayHeaders 文本仍在 calendar_math.dart，不动。

## 验证（Verification）

- grep 断言：`lib/features/calendar/` 下不再 import countdown/subscription/
  timetable 的任何文件。
- 新增测试：注册一个假贡献者即可向月历注入条目（证明扩展点生效）；
  copyWith(error: null) 清除错误的回归用例（先红后绿）。
- `flutter analyze` 0 error/0 warning；现有测试全绿；
  月历渲染行为目视比对（倒计时条排序、淡化渲染、休息日标记不变）。

## 实施记录（2026-11-18，与 ADR-0002 子项 4–6 同批）

- **贡献者端口**：`lib/core/ports/timeline.dart` 新增 `TimelineTag` /
  `TimelineBarEntry` / `TimelineContribution`（tagsOn 闭包 + bar 快照）
  与 `CreateCountdown` 命令 typedef；纯 Dart，不依赖 Flutter。
- **装配器上移**：`lib/bootstrap/timeline.dart` 的
  `timelineContributionsProvider` 聚合 subscription/timetable/countdown
  三个贡献者 Provider（各 feature controller 文件末尾追加贡献者定义，
  只暴露只读快照）；`createCountdownProvider` 把「创建倒数日」命令注入
  calendar 读侧，calendar 不再 import 兄弟 feature。
- **文件拆分**：calendar_controllers.dart 拆为
  application/calendar_controller.dart（写侧命令 + 导航/选中态）、
  presentation/read_model/month_data.dart（EventOccurrence /
  CalendarDayModel / MonthData 等表现层塑形）、
  presentation/calendar_providers.dart（provider 组合与 monthDataProvider）。
- **cells Map 化（ADR-0002 子项 4）**：CalendarState.cells 改
  `Map<DateKey, DayCell>`，_cellOf O(1)；copyWith/load/全部读取点同批改完。
- **增量 load（ADR-0002 子项 5）**：saveCell/saveEvent 落盘成功后乐观更新
  state 对应单项；全量 load 只留给初次加载与跨 engine 广播；写失败不更新。
- **error 哨兵**：`copyWith` 用 `static const Object _errorUnset = Object()`
  哨兵替代 error/clearError 双开关，`copyWith(error: null)` 可清除错误。
- **存储合一（ADR-0002 子项 6）**：JsonEntityStore 增加 `idField`
  （cells 用 'date'）与可选 logger；LocalCalendarRepository 重建为薄委托，
  特殊性只剩「两个列表 + pullDomainEvents」。
- **回归测试**：test/calendar_read_model_test.dart 7 例（假贡献者注入、
  倒计时条排序、淡化/休息日塑形等）；calendar_repository_test.dart 增 3 例
  增量更新（共 8 例）；test/calendar_provider_chain_test.dart 1 例
  （全链路 Provider 构建 + microtask load 后无 error 态，由运行期诊断
  用例转正）。
- **门禁**：grep 断言 `lib/features/calendar/` 下 countdown/subscription/
  timetable import 计数 = 0；根 `flutter test` 62 全绿；core 154、
  设计系统 14 全绿；`flutter analyze` 0 error / 0 warning（52 条 material
  弃用 info 为 ADR-0009 前基线）；`flutter build windows --debug` 通过；
  双 engine 冒烟 3×95 秒健康（overlay region/hit semantics 全对，
  详见 ADR-0010 验证节）。
- **运行期缺陷同批修复**：子 engine 整份 RegisterPlugins 触发
  auto_updater 进程级单例 abort，改注册子集；runner /utf-8 解决 C4819。
  决策与证据独立落 ADR-0010。
