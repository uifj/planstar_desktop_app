## 背景（Context）

勾选一个 checkbox 的真实代价（链路已逐段核实）：

1. `_cellOf(date)` 对 `state.cells` 线性扫描（calendar_controllers.dart:201-206）。
2. `LocalCalendarRepository.saveCell` → `_cells.readAll()` 全量 jsonDecode →
   removeWhere+add → `writeAll` 全量 jsonEncode → store.write
   （local_calendar_repository.dart:126-138）。
3. `JsonListStore`（packages/infras/core/lib/src/storage/json_list_store.dart:41-82）
   **无内存缓存**，readAll 每次 `_store.read` + jsonDecode；类注释（:10-12）
   「数据量小（几十条）、读写频率低」的假设已不成立：cells 每天最多一条、
   events 随使用无限增长，读写频率是「每次勾选」。
4. DataHub 原生侧全量序列化整个 entries map + `MoveFileExW(MOVEFILE_WRITE_THROUGH)`
   写穿盘 + 广播全部 engine（data_hub_plugin.cpp:137-163/247-275/277-295）。
   Dart 侧 read 虽走内存 `_entries`（data_hub.dart:210），每次仍全量 jsonDecode。
5. 命令随后 `await load()` 全量重读 events + cells（calendar_controllers.dart:87-104，
   写后调用点 :220/:227 等）→ `monthDataProvider` 全量重算（见 ADR-0001）→
   全部单元格重建；广播到达其他 engine 后各自再跑一遍。

合计每勾一次：≥3 次全量 jsonDecode + 1 次全量 jsonEncode + 1 次原生全量序列化
+ 1 次写穿盘 + N engine 广播 + 全月历重算。

放大因素与并行实现：

- `autoDelayUncompleted` 对每个待顺延事件逐个 `await saveEvent`
  （calendar_controllers.dart:192-194），最后再一次 load()（:196）；
  `JsonEntityStore.upsertAll` 批量能力已存在（json_entity_store.dart:66-79），
  但 LocalCalendarRepository 无对应 `saveEvents`。同函数 :188-190 用无 break
  的 for 循环判断 completedDates 是否含 startDate，`contains` 一行可替代。
- **双层映射**：JsonEntityStore 内层恒等 fromJson/toJson
  （json_entity_store.dart:31-36）+ 外层真映射（:47-52）；
  LocalCalendarRepository 同构（local_calendar_repository.dart:30-41 + :55-59/:108-111）。
- **_persist/_dispatch 逐字重复**：json_entity_store.dart:96-110 vs
  local_calendar_repository.dart:168-185（唯一差异是后者多一条 debug 日志）。
  calendar 走 LocalCalendarRepository，notes/countdown/timetable/subscription/history
  走 JsonEntityStore——改缓存/批量/错误语义要改两遍。
- **Result 失败传播五件套重复 7 次**：LocalCalendarRepository 4 处
  （:75-79/:91-95/:127-131/:142-146）、JsonEntityStore 3 处（:55-60/:70-75/:82-86）。
  核实修正：core 包 `flatMap` **已存在**（packages/infras/core/lib/src/result/result.dart:61），
  缺的是**异步组合子**；`guardAsync` 目前在应用层 lib/core/result_x.dart:9-22（仅 23 行），
  `requireData` 在 core 包 result.dart:38-42。
- **死代码**：`SharedPreferencesStore`（lib/infrastructure/storage_adapters.dart:17-53）
  全项目零实例化；shared_preferences 的 Dart import 仅此一处（:9）。
  bootstrap.dart:51-52 注释明说「不再使用 SharedPreferences」；
  data_hub.dart 只用旧文件名常量做迁移（:32/:437-455），不 import 该包。
  核实修正：bootstrap.dart:54-56 的 FlutterSecureStorageAdapter 是 SecureStore
  适配器（storage_adapters.dart:59-79），与 SharedPreferencesStore 无关。
- `DateKey` 值相等已核实可作 Map key：value_objects.dart:11（extends ValueObject）、
  :54-55（props => [key]）；core 包 value_object.dart:31-35（==）/:37-41（hashCode）。

## 决策（Decision）

七个可独立交付的子项，按风险从低到高排序：

1. **JsonListStore 加内存缓存**（投入产出比最高）：缓存解码后的列表；
   `writeAll` 同步更新缓存；新增 `invalidate()`。失效条件只有两个——自己写、
   收到 DataHub 广播（infrastructure 层在 CrossEngineSync 回调里调 invalidate，
   core 包保持零 Flutter/零 DataHub 知识）。**readAll 必须返回防御性副本**：
   现有 saveCell 直接对 readAll 结果 removeWhere+add，返回缓存原实例会被污染。
2. **补 `saveEvents` 批量写**：LocalCalendarRepository 增加批量 upsert（一次
   readAll/writeAll/落盘/分发），autoDelayUncompleted 改批量 + `contains` 替代循环。
3. **Result 异步组合子**：core 包 Result 增加 `flatMapAsync`（异步版 flatMap），
   `guardAsync` 从 lib/core/result_x.dart 下沉 core 包（单一真实源），
   7 处五件套塌成单行链式调用。core 包改动须过 `dart test`。
4. **cells 换 `Map<DateKey, DayCell>`**：CalendarState.cells 改 Map，_cellOf O(1)。
   波及 copyWith/load/presentation 读取点，与 ADR-0004 的文件拆分同批做。
5. **load() 改增量**：saveCell/saveEvent 落盘成功后乐观更新 state 中对应一项；
   全量 load 只保留给初次加载与跨 engine 广播路径。写失败（Fail）不更新 state，
   保持现有 Result 错误语义。
6. **统一存储原语**：消除内层恒等映射；把 `_persist/_dispatch` 收敛为一份实现
   （JsonEntityStore 支持多列表，或抽出共享 JsonCollection 原语），
   LocalCalendarRepository 重建其上，特殊性只剩「两个列表 + pullDomainEvents」。
7. **删除 SharedPreferencesStore 与 shared_preferences 依赖**：删适配器、
   删 pubspec 条目，重新 pub get 核实 win32 解析面（现有 file_picker 11.x /
   flutter_secure_storage 10.x 锁版本是否可松动以实测为准，不预先承诺）。

候选取舍：
- 「直接上 drift/SQLite 替代 JSON 存储」：收益更大但改存储格式、涉及多 engine
  并发与迁移，风险高，单独立项为 ADR-0008；本 ADR 是不改存储格式的最优解。
- 「原生侧增量落盘」：DataHub 的全量快照 + 回滚语义是已验收的正确性设计
  （docs/cross-engine-sync-analysis.md §4.1，2026-11-16 验收），当前数据量下
  原生写盘不是主要矛盾，暂不动；通道层改造见 ADR-0007。

## 后果（Consequences）

- **正面**: 勾选延迟从「全量读写 × 多 engine」降为「单项更新 + 一次落盘」；
  重复 jsonDecode 全消；两份存储实现合一，后续缓存/批量/错误语义只改一处；
  死代码与一个 win32 依赖方移除。
- **负面/风险**: 缓存失效漏接广播会造成跨 engine 脏读（须有回归测试兜底）；
  乐观更新与广播重读之间短暂双路径，需保证幂等；cells 改 Map 波及面较广。
- **中性**: core 包 Result/存储原语能力增强，其他 feature 顺带受益。

## 验证（Verification）

- 新增回归：写→广播→读一致性（含 invalidate 路径）；缓存返回副本不可被
  调用方 mutation 污染；saveEvents 一次落盘（以 store.write 调用计数断言）。
- 现有根工程 36 测试 + core 包测试全绿；`flutter analyze` 0 error/0 warning。
- 基准：同一勾选操作前后对比 jsonDecode 次数与耗时（DevTools timeline 或
  计数桩），记录数据回填本 ADR。
- 双 engine 冒烟：主窗口与桌面组件同时勾选同一天，两端一致
  （tasklist 核实进程，AGENTS.md §7）。
- grep 断言：`SharedPreferencesStore` 与 `import 'package:shared_preferences`
  在 lib/ 下零残留。

## 实施记录（子项 1–3，2026-11-18）

- **JsonListStore 缓存**：实现为「原始串标签」缓存而非手动 invalidate 接线——
  readAll 仍读一次底层（DataHub 是内存查表，data_hub.dart:210），原始串与
  缓存标签一致则跳过 jsonDecode/fromJson，返回 `List.of` 防御性副本；
  writeAll 成功后同步更新缓存；clear/键删除重置缓存。
  **refinement 理由**：DataHub 广播先把新值写进 `_entries` 再发 DataChange
  （data_hub.dart:189-206），原始串比较天然覆盖跨 engine 失效，不存在
  「漏接广播」路径（本 ADR 风险清单第一条被设计消除），故未新增无调用方的
  `invalidate()` 公开 API。元素级只读约定写入类注释。
- **saveEvents 批量**：CalendarRepository 端口新增 `saveEvents`，
  LocalCalendarRepository 一次 readAll/writeAll/落盘/合并分发；
  `autoDelayUncompleted` 改收集后单次批量写，`contains` 替代无 break 循环，
  空集合零开销直接返回。
- **Result 组合子**：core 包新增 `flatMapAsync` 与顶层 `guardAsync`
  （保留 LOCAL_IO_ERROR 语义）；lib/core/result_x.dart 删除，3 个 import 方
  改指 package:core/result.dart；五件套塌缩共 8 处（日历仓储 4 + JsonEntityStore 3
  + 设置仓储 save 1）。
- **回归测试（先红后绿）**：core 新增 11 例（缓存命中计数桩 fromJson 调用数、
  防御性副本、外部直写/删键可见性、clear 残留、append 裁剪、flatMapAsync
  三分支、guardAsync cause 保留）；根工程新增 test/calendar_repository_test.dart
  5 例（批量一次落盘以 write 计数断言、同 id 覆盖、先落盘后分发/写失败不分发、
  空列表零开销、autoDelay 两事件合并一次写且只顺延该顺延的）。
- **门禁**：core `dart test` 154 全绿（143 基线 + 11）；根 `flutter test`
  51 全绿（46 基线 + 5）；`flutter analyze` 0 error / 0 warning
  （53 条 material 弃用 info 为 ADR-0009 前基线）；改动文件已 dart format。
