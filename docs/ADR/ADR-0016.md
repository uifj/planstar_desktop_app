# ADR-0016: 桌面端事件分发、多窗口写入、导入与重复规则存在一致性缺口

- **状态**: PROPOSED
- **分类**: DEF
- **优先级**: P0
- **影响维度**: 生产功能
- **日期**: 2026-11-24
- **来源**: 桌面端专项源码核验
- **修复 commit**: `5931e61`（仅非 Windows fallback DataHub 并发写入子项）

> 仅登记，暂不修复业务逻辑和存储格式。以下问题可能导致写入丢失或界面结果与落盘结果不一致。

## 背景（Context）

1. `LocalCalendarRepository.saveEvent()` 在调用 store 前执行 `event.pullDomainEvents()`；store 虽在写成功后才分发事件，但写入失败时事件已被取走，重试同一聚合会丢失事件。证据：`lib/features/calendar/infrastructure/local_calendar_repository.dart:74-86`、`:168-184`。
2. 审计时 macOS 等非 Windows 平台的 `_LocalBackend` 只在单个实例内串行化写入队列，两个 engine 可各自持有旧 `_entries` 快照并整表覆盖同一 `planstar_data_hub.json`。`5931e61` 已改为独占文件锁、锁内重读磁盘、按磁盘 revision 写入和唯一临时文件原子替换；JSON 格式未变。证据：`lib/infrastructure/data_hub.dart`、`test/data_hub_test.dart`。
3. 导入文件选择允许 JSON/TXT/CSV，但导入始终调用 `jsonDecode`，因此 TXT/CSV 不能按所选格式解析；`saveCell`/`saveEvent` 返回的 `Result` 被忽略；逐条写入没有事务或回滚。单元格冲突按日期判断，事件始终按 ID 替换，`replaceConflicts=false` 不会跳过已存在事件；`existingDates` 仅用于完成消息中的计数。证据：`lib/features/transfer/application/transfer_controller.dart:158-203`、`lib/infrastructure/file_gateway.dart`。
4. JSON 导出始终输出完整快照，不应用界面选择的日期范围；TXT/CSV 会按范围过滤，但自定义范围缺少起点或终点时 `effectiveRange` 回退为 `null`，仍导出全量。证据：`lib/features/transfer/application/transfer_controller.dart:50-112`、`:117-147`。
5. `occurrences()` 返回 `List<DateKey>`，不会返回 `null`；默认最多扫描 4000 天，且 `count` 在日期进入请求范围之前就已计数，因此结果可能少于 `count`。`happensOn()` 不检查 `count` 或 4000 天上限，与 `occurrences()` 的边界行为不一致。证据：`lib/features/calendar/domain/recurrence_policy.dart:14-61`。

## 决策（Decision）

- 暂不修改存储格式、仓储契约或上述业务实现。
- 后续先补可稳定复现的失败注入与业务回归测试，再分别处理事件生命周期、导入原子性和重复规则边界；非 Windows fallback DataHub 并发写入已由 `5931e61` 修复并以双实例测试锁定。
- 若需引入共享 SQLite 或改变 DataHub 格式，必须遵守 AGENTS.md，事先获得用户确认，并与 master 分支历史 ADR-0008 的存储终态决策协调；该历史文件不在当前 legacy 分支中。
- 导入修复应明确支持格式、冲突键、错误语义与回滚边界，不能只通过收窄文件选择器掩盖解析不一致。

## 后果（Consequences）

- **正面**: 为数据丢失类高风险问题建立可追踪基线，避免后续优化覆盖已有不变量。
- **负面/风险**: 多 engine 并发修复可能触及存储格式；需要同时验证 Windows Pigeon 后端与非 Windows 本地后端。
- **中性**: 除已修复的 DataHub 并发写入子项外，本记录不改变现有业务实现、用户数据格式或端口契约。

## 验证（Verification）

- 注入首次写入失败，确认重试后 `DomainEvent` 仍恰好分发一次；写成功时分发顺序与落盘顺序一致。
- 已完成 DataHub 子项：两个 `DataHubStore(forceLocal: true)` 实例并发写不同键与同键，断言最终同时保留双方结果、revision 连续且无临时文件残留；macOS 原生多 engine 同步另由 ADR-0020 的运行证据覆盖。
- 使用 JSON、TXT、CSV、损坏 JSON、部分字段非法和磁盘写入失败夹具验证导入；任一失败都应给出明确结果，并满足约定的事务边界。
- 对选中区间与全区间分别导出，断言结果集严格符合选择。
- 对每日、每周、每月、农历重复及超过 4000 天上限的 `count` 做 `occurrences()`/`happensOn()` 对拍，保证次数、例外日和终止日一致。
