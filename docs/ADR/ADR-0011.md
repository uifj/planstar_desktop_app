# ADR-0011: 按钮主题 minimumSize 禁用无限宽，修复 Row 内布局抛异常导致整页空白

- **状态**: IMPLEMENTED（待提交）
- **分类**: DEF
- **优先级**: P0
- **影响维度**: 生产功能 / 评估阻断
- **日期**: 2026-11-19
- **来源**: 用户手动测试反馈（主窗口日历纯白）+ 运行时渲染树审计
- **修复 commit**: e641af2

## 背景（Context）

- 现象：主窗口标题栏与左侧导航正常渲染，日历区域整块纯白；主窗口内编辑面板与
  对话框的按钮区同样不出现。桌面浮层月历渲染正常。
- 触发链（旧主题契约）：`filledButtonTheme` / `outlinedButtonTheme` 使用
  `minimumSize: Size.fromHeight(44)`，即 `Size(double.infinity, 44)`。
  material_ui 1.11.1 的 `ButtonStyleButton.build` 把子节点包进
  `_InputPadding(minSize, child: ConstrainedBox(effectiveConstraints, …))`
  （pub cache `material_ui-1.11.1/lib/src/button_style_button.dart:624-627`，
  约束合成见 `:501-508`）；Windows 的 `VisualDensity.adaptivePlatformDensity`
  为 compact(−2,−2)，把 44 压成 36。`Row` 给非 flex 子节点无限宽，
  `RenderConstrainedBox.performLayout` 的 `enforce()` 于是产出**紧约束无限宽**，
  抛 `BoxConstraints forces an infinite width`。
- 冻结机制：SDK `packages/flutter/lib/src/rendering/object.dart:2928-2944` 在
  `performLayout()` 抛异常后捕获上报，但仍置 `_needsLayout = false` 并
  `markNeedsPaint()`。抛异常的节点 size 保持 MISSING（`debugResetSize()` 不清
  size），其脏后代被永久 orphan——整条路由子树空白，而引擎继续出帧，
  控制台在 Windows GUI 子系统下又看不到异常输出，故表现为「静默纯白」。
- 运行时证据：VM service `ext.flutter.debugDumpRenderTree` 的最深
  MISSING+clean 原点节点为 `RenderConstrainedBox`，约束
  `BoxConstraints(w=Infinity, 36.0<=h<=Infinity)`，creator 链指向
  `CalendarTitleBar`（`calendar_title_bar.dart:33` 的 Row、`:49` 的
  OutlinedButton「今天」）。修复前渲染树 527 laidOut / 1318 NEEDS-LAYOUT /
  1332 sizeMissing；修复后 1889 / 0 / 0。
- 回归用例先红：`button_layout_test.dart` 在旧主题下复现同一异常级联
  （`hasSize` 断言失败链），改主题后转绿。
- 归属：该契约缺陷引入自 fd28819，早于本轮 ADR-0001…0010 实施，非本轮改动引入。
- **为什么升级前「功能正常」（2026-11-19 补充取证）**：无限宽校验整段包在
  `assert(() { … }())` 内——`BoxConstraints.debugAssertIsValid` 在
  Flutter 3.41.9（Dart 3.11.5，`rendering/box.dart:547`）与
  3.50.0（`rendering/box.dart:552`）中结构逐字一致，`forces an infinite width`
  分支同样在断言内。**Release/AOT 剥离断言后该路径不抛异常**，只有 Debug 会
  触发冻结。旁证：`material/button_style_button.dart` 在两版 SDK 间逐字节相同；
  `BoxConstraints.enforce` 相同；material_ui 1.11.1 与 SDK 3.50 的同名文件
  仅 47 行差异（文档注释 + `isSelected` 形参），约束合成路径一致；
  `AppTheme.light()/dark()` 的 MaterialApp 接线与 `CalendarTitleBar` 的
  Row + OutlinedButton「今天」结构相对 HEAD 均未改变（仅格式化与 provider 改名）。
  结论：这不是 Flutter 3.50 的行为回归，而是潜伏契约缺陷在 Debug 下显形；
  本轮因 Release 在本机启动期崩溃（ADR-0010/0012）改用 Debug 验证，才暴露出来。

## 决策（Decision）

1. 两处主题 `minimumSize` 改为 `const Size(0, 44)`：保留 44 的高度契约，
   宽度交给子内容与父约束决定（`app_theme.dart:132`、`:147`）。
2. 候选取舍：
   - 给 Row 内按钮逐个包 `Flexible/Expanded`：只修单点，其余 Row/Wrap 调用点
     仍会触发同一异常，弃。
   - 全局改 `VisualDensity`：影响所有控件密度，且 infinity 宽隐患仍在，弃。
   - 主题层改有限宽（选定）：根因单点、全应用受益，且可被 widget 测试门禁守住。
3. 不在渲染层加兜底或吞异常：根因是主题契约，加兜底只会掩盖下一次同类错误。
4. 撤销排查期间的临时 workaround：`windows/runner/main.cpp` 的
   Impeller Disabled 开关与 `vendor/desktop_multi_window` 本地 override 均已
   移除；默认 Impeller 下主/子双 engine 初始化与渲染验证通过。间歇
   0xC0000005 崩溃按 ADR-0010 登记为 Intel 驱动环境风险，不在本 ADR 处理。

## 后果（Consequences）

- **正面**: 主窗口日历恢复完整渲染；所有「Row/Wrap 内放主题按钮」的路由同因同修，
  包括 `cell_editor_panel.dart:154/165/178`、`event_editor_dialog.dart:110/114/152/229/273/290`、
  `context_dialogs.dart:74/78`、`note_editor_dialog.dart:67/175/189`——
  用户反馈的「编辑面板有问题」与日历纯白是同一根因。
- **负面/风险**: `minimumSize` 宽度语义由「无限」变为 0，按钮在无限宽约束下不再
  自我撑满；现有调用点均由 Row/Wrap/父约束定宽，截图核对无视觉回归。
- **中性**: 设计系统新增布局回归门禁（DS 测试 14 → 16）；桌面浮层不含
  `ButtonStyleButton`（grep 仅 IconButton 与自绘 `_toolButton`），不受本缺陷影响。

## 验证（Verification）

- `cd packages/infras/core_design_system && flutter test` → 16 绿；
  把 `minimumSize` 改回 `Size.fromHeight(44)` 时 `button_layout_test.dart` 两例红。
- `flutter analyze` 0 issue；根 `flutter test` 82 绿；
  `cd packages/infras/core && dart test` 154 绿。
- `flutter build windows --debug` 通过；运行时 `PrintWindow` 截图主窗口为完整
  月历（含用户数据色块），`debugDumpRenderTree` 统计 1889 laidOut / 0 NEEDS-LAYOUT /
  0 sizeMissing。
- 桌面浮层：`verify_desktop_widget.ps1` 命中区域自检；编辑态截图确认快速输入行与
  八项工具栏齐全；浮层编辑链路另行人工复核（合成点击会被前景窗口遮挡，不可靠）。
