# ADR-0012: 摘除 auto_updater 依赖，登记 ANGLE×Intel 启动期 AV 取证与运行时验证工装约束

- **状态**: IMPLEMENTED（待提交）
- **分类**: DEP
- **优先级**: P0
- **影响维度**: 生产功能 / 评估阻断 / 验证可信度
- **日期**: 2026-11-19
- **来源**: 用户指令「先将 auto_updater 注释」+ 安装版启动崩溃取证 + Dart 3.14 AOT 缺陷排查
- **修复 commit**: —

## 背景（Context）

1. **auto_updater 是本轮迁移新增依赖，且 Dart 层零调用**。
   `git diff HEAD -- pubspec.yaml` 显示旧基线（Dart 3.11.5 / Flutter 3.41.9）
   没有 auto_updater；本轮为「桌面能力补齐」加入 `auto_updater: ^1.0.0`。
   全仓库 grep 仅 pubspec 一行 + runner 注释，无任何 Dart 调用。
   其 Windows 实现 `AutoUpdater` 是进程级单例，第二次构造
   `throw std::invalid_argument` → 未捕获 → abort() 冻死主平台线程
   （ADR-0010 已用 WER dump 0xE06D7363 定位）。ADR-0010 的缓解措施是
   「子 engine 只注册安全子集」，属于**绕过**而非消除：主 engine 仍构造该单例，
   子集清单需与 registrant 人工同步，是长期维护负担。
2. **启动期 0xC0000005 属 ANGLE D3D11 × Intel 驱动，Debug/Release 双引擎均间歇**。
   符号取证（dbghelp + SDK 引擎 PDB 离线解析，无 cdb 环境）：
   - Release：`flutter_windows.dll+0xc2f416` →
     `rx::StateManager11::syncUniformBuffersForShader`
   - Debug：`flutter_windows.dll+0xef4478` → `rx::StateManager11::syncProgram`
     （2026-11-19 19:39:17 WER Id=1000，进程 0xD5B4）
   - Debug：`flutter_windows.dll+0xf311bc`（ADR-0010 记录的 Impeller 启动期偏移）
   - 另有故障帧全部落在 Intel 用户态驱动 `igd10umt64xe.DLL`
     （32.0.101.8509）的样本，项目模块无故障帧。
   `rx::` 命名空间即 ANGLE 的 D3D11 后端，故两条渲染路径（Impeller 与 Skia GL）
   都经过同一翻译层。环境开关 A/B：`FLUTTER_ENGINE_SWITCHES` +
   `enable-impeller=false`、`enable-software-rendering=true` 均仍复现同签名崩溃；
   Windows engine **无 `use-angle` 开关**。产物哈希与构建产物一致，排除陈旧引擎。
   结论：与 Dart 侧 `win32` FFI 包（5.15.0，transitive）无关，
   与 desktop_multi_window 无关；根治手段是更新 GPU 驱动。
3. **Dart 3.14.0 的 AOT P0（`linearscan.cc:3013: unreachable code`）未命中本项目**。
   该缺陷是**编译期** gen_snapshot abort，触发形态为「非 late 的
   definite-assignment `final` 局部变量 + sealed switch 分支内赋值 +
   switch 之后在闭包中读取」。本项目唯一 sealed 类是
   `packages/infras/core/lib/src/result/result.dart:16` 的 `Result<T>`，
   全仓库无对它的模式匹配 switch（`case Success(:final data)` 仅存在于文档注释）；
   grep 未初始化 final 局部变量命中的全是类字段。
   实证：摘除 auto_updater 后 `flutter build windows --release` 成功（156.9s）。
4. **运行时验证工装此前不可信**，导致「合成点击无效」被误判为应用缺陷：
   - 屏幕最上层存在全屏 `Chrome_RenderWidgetHostHWND`（Electron 窗口），
     `WindowFromPoint` 在任意坐标都返回它，全局合成点击全部落在该窗口；
   - PowerShell 5.1 按 GBK 读取无 BOM 的 UTF-8 脚本，中文注释尾字节可吞掉换行，
     使下一行代码被并入注释（DPI 感知调用因此静默失效）；
   - DPI 不感知进程的 `GetSystemMetrics` 在 150% 缩放下被虚拟化（1707×1067
     而非 2560×1600），绝对坐标换算错误；
   - 自定义函数名 `LP` 与内置别名 `Out-Printer` 冲突；
   - 用户会并发手动操作被测应用，全局光标注入与用户输入互相干扰。

## 决策（Decision）

1. **摘除 auto_updater 依赖**：pubspec 注释保留并写明恢复条件
   （未来接线时只能注册在主 engine）。`flutter clean` + `flutter pub get`
   让工具重新生成 registrant / generated_plugins.cmake，**不手改成品**。
   ADR-0010 的子 engine 安全子集策略保留（其余插件同样需评估多 engine 安全性）。
2. **启动期 AV 维持环境风险登记，不在项目代码内加 workaround**：
   延续 ADR-0010 决策 3。复现时先收 WER dump 核对 ExceptionAddress 归属，
   再考虑更新 GPU 驱动；不得以放宽冒烟门禁「变绿」。
3. **本机暂装 Debug payload**（用户已批准）：Release 在本机启动间歇崩溃，
   为让用户能手动验收，`install.ps1 -Source build\windows\x64\runner\Debug`。
   这是**临时**安排，根治后回到 Release；不因此改变发布产物形态。
4. **运行时验证改用窗口消息注入**：`PostMessage` 直接投递到
   `FLUTTERVIEW` 子窗口句柄（经 `GetWindow(top, GW_CHILD)` 取得），
   坐标用 `ClientToScreen` 换算，绕开前景遮挡与全局光标竞争。
   工装脚本约束：ASCII 注释、进程先设 PerMonitorV2 DPI 感知、
   函数名避开 cmdlet 别名、写盘归因需静默窗口（前后两次读取一致才注入）。
5. **不为 Dart 3.14 AOT 缺陷加任何规避改写**：未命中，且修复已进 Dart stable
   （3.14.1），Flutter 3.50.1 未发布。

候选取舍：
- 「保留 auto_updater + 给注册包 try/catch」：掩盖进程级单例契约，
  且 abort 发生在 CRT 层难以可靠拦截（ADR-0010 已弃用），本轮进一步摘除依赖。
- 「删除 desktop_multi_window 改自研原生多窗口 + Pigeon」：Pigeon 是通道代码
  生成器，不能替代窗口/引擎创建；该替换修不了上述任何故障，却要自行接管
  引擎生命周期、DPI、z-order、命中区域。耦合面虽薄（lib 内仅
  `infrastructure/desktop_adapters.dart` 一处 import，背后是 MultiWindowGateway
  端口），仍登记为**独立架构议题**，不在本轮实施。
- 「继续用全局 SendInput 做点击验证」：被全屏 Electron 窗口与用户并发操作
  双重干扰，结论不可信，弃用。

## 后果（Consequences）

- **正面**: 子 engine abort 的根因（进程级单例插件）从依赖层面消失；
  registrant 与子集清单不再需要为 auto_updater 人工同步；
  运行时验证有了可归因的注入通道。
- **负面/风险**: 自动更新能力缺口扩大——从「已声明未接线」变为「依赖已摘除」，
  恢复时需同时解决多 engine 注册与 appcast 更新源；
  本机 Debug 安装体积与性能不代表发布形态；
  Intel 驱动 AV 仍可能间歇打断任何一次冒烟，需重试而非改门禁。
- **中性**: ADR-0010 的子 engine 子集策略、DataHub Pigeon 通道均不变。

## 验证（Verification）

- `flutter clean` + `flutter pub get`：移除 auto_updater / _macos /
  _platform_interface / _windows 共 4 包；`generated_plugin_registrant.cc`
  与 `generated_plugins.cmake` 由工具重新生成，grep 确认无 AutoUpdater 注册。
- `flutter build windows --debug` exit 0；`flutter build windows --release`
  exit 0（156.9s）→ AOT 未命中 Dart 3.14 gen_snapshot 缺陷。
- 符号解析：`rx::StateManager11::syncProgram`（Debug +0xef4478）、
  `rx::StateManager11::syncUniformBuffersForShader`（Release +0xc2f416）。
- **Release 构建+运行冒烟（2026-11-19 20:49–20:52，直跑 build 产物）**：
  `flutter build windows --release` 45.9s 成功；但默认渲染 5 次 +
  `enable-software-rendering=true` 2 次启动均在 12–15s 内崩溃（7/7）。
  WER 0xc0000005 故障模块均为 `flutter_windows.dll`。用 **windows-x64-release**
  引擎 PDB 解析（其 DLL 哈希 a82241d4… 与 build 产物一致）：
  +0xc2f6aa→`rx::StateManager11::syncUniformBuffersForShader`、
  +0xc2c4b2→`rx::StateManager11::updateState`、
  +0xc69e5c→`rx::ProgramExecutableD3D::getUsedImageRange`，
  与登记的 ANGLE×Intel 启动期 AV 同族，**非项目代码、非 Release 回归**。
  工装陷阱：SDK `windows-x64` 目录是另一引擎变体（0ffdbdef…），误用其 PDB
  会解析出 `rx::ContextVk`/`SemaphoreVk` 等 Vulkan 假符号；Release 必须用
  `windows-x64-release`。结论：本机更新 Intel GPU 驱动前 Release 不可运行；
  维持用户批准的临时 Debug 安装（本轮留跑 pid 25420）。
- 门禁：`flutter analyze` 0 issue；根 `flutter test` 83 绿（含 ADR-0013 新增
  回归）；`packages/infras/core` `dart test` 154 绿；设计系统 16 绿；
  改动文件 `dart analyze --fatal-infos` 0。
- 运行时同步验证（2026-11-19 晚，安装版 Debug）：
  - **主→浮层（受控、可归因、已复原）**：主窗口设置「显示农历」开关两次点击，
    DataHub revision 15→16→17 与点击一一对应，`showLunar` false→true；
    浮层截图像素随之失去/恢复全部农历文字（其余内容不变）。
  - **浮层→主（_live 证据，非受控）**：用户并发在某一窗口给 11/21 添加「123」，
    同一轮 `PrintWindow` 截图中主窗口与浮层均显示该行 → 跨 engine 单元格
    传播在运行时成立；受控反向写入未能完成（见下）。
  - **位置持久化**：修复 ADR-0013 后启动截图 bbox 逻辑 (640,16,1000,1016)
    与盘上 `planstar.desktop.card.v2` 逐字一致。
- 注入通道能力边界（本轮实测，登记为验证缺口而非应用缺陷）：
  - 主窗口 `FLUTTERVIEW` 的 PostMessage 点击**被消费**（设置页/ tab /开关均生效）；
  - 浮层子窗口的 PostMessage 点击**未观察到任何消费**（标记完成/添加一行/
    输入行聚焦均无写盘、无焦点变化），WM_MOUSEMOVE 与 WM_CHAR/WM_KEYDOWN
    在主/浮层均不消费 → 拖拽与文本输入无法合成；
  - 向浮层注入点击的时间点与 Intel 驱动 AV（`igd10umt64xe.DLL+0xd61b0` /
    `+0xd5cf0`，20:32:53 / 20:35:53）聚集，不能排除合成指针事件触发驱动
    缺陷路径；**停止向浮层注入**，浮层交互编辑的运行时验证改由用户手测覆盖。
  - 结论：浮层→主的受控写入验证、浮层逐行编辑/调色板/工具栏的运行时验证
    仍为缺口，已由代码审计 + 跨 engine 集成测试 + 上述 live 传播证据部分覆盖。
